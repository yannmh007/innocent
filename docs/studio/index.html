Start-up

Two different costs, and only one of them is about file size. Bitrate — megabits every second — decides whether a stream can keep up at all: a phone camera writes for archive quality, so a short clip can demand more per second than a whole feature and will stop and start for as long as anyone watches it. Speed test downloads 8 MB of a real file through the Worker, from this phone, so the two numbers can be compared instead of guessed at. The index is the second cost: an MP4 keeps one, and at the FRONT a player reads the head of the file and starts. At the END, it reads the head, finds no index, and seeks to the tail of a file that may be gigabytes away — one extra round trip before the first frame, which is a slower start rather than a stutter. Uploads made before the console learned to write the index first are in the second state, and re-uploading them from here is the fix.

Streaming copies

Every viewer gets the copy their connection can carry, chosen by their phone from what it has measured. Heavy uploads are queued for conversion automatically; anything older can be queued here. A job starts within five minutes and reports each size as it finishes, so the small one is watchable long before the big one is done — queued is waiting, running is being converted, ready has a full set.

Stream secret

The shared secret between the streaming Worker and request-playback. Generate it once, paste the same value into both — Cloudflare (Worker → Settings → Variables and Secrets → TOKEN_SECRET) and Supabase (Edge Functions → Secrets → STREAM_TOKEN_SECRET). It is never sent anywhere from this page.
32 random bytes. There is no required format — both sides hash whatever text they are given — so a password-manager output works just as well as this. Generating a new one invalidates every token already handed out, so anything mid-playback stops until the app asks again, which it does automatically.
